01 — What Mintlify, Fern & Speakeasy Are Doing
Most Advanced

Mintlify

Started with RAG → upgraded to Agentic Retrieval in 2025. Uses Claude 4.

  • Agentic RAG (LLM decides what to search)
  • Claude 4 with expanded context window
  • Auto-indexes published docs on deploy
  • MCP server generated per docs site
  • llms.txt / llms-full.txt (Markdown not HTML)
  • Citations + source links in responses
  • 1M+ queries served routinely
Standard RAG

Fern

Simple, solid RAG for API docs. Core product is SDK generation — chatbot is a companion.

  • Standard RAG (one-pass retrieval)
  • Crawls API reference + docs
  • Semantic search index over content
  • Embedded chat widget
  • Good for: "how do I use this endpoint?"
  • Struggles with multi-hop questions
Pivoted

Speakeasy

Pivoted to enterprise AI control plane — not a docs chatbot anymore.

  • Enterprise MCP gateway
  • Govern, route, audit agent tool calls
  • AI assistants that execute CLI workflows
  • Role-based access from identity provider
  • Agentic — but for doing things, not answering
  • Different product category entirely

07 — Where You Can Beat Mintlify / Fern
🔍 Retrieval

Hybrid Search (BM25 + Vector)

Most implementations only do vector search. Combining BM25 catches exact matches on API names, error codes, and function signatures that pure semantic search misses. Use alpha-weighted fusion: score = α·bm25 + (1-α)·vector

✍️ Pre-retrieval

Query Rewriting

Before searching, rewrite vague user queries into retrieval-friendly ones using a cheap model. "it's not working when I do auth" → "authentication error troubleshooting steps". One extra call, massive retrieval gain.

💬 Memory

Real Multi-turn Conversation

Keep conversation history with sliding window + summarization. When the user says "do the same for Python" after asking about JavaScript — the system understands the reference. Use mem0 or a Redis conversation buffer.

📈 Improvement Loop

Feedback-Driven Optimization

Capture thumbs up/down per response + failed queries (zero results). Feed this into reranking weights, chunk improvements, and content gap detection. This compounds — your bot gets better over time automatically.

08 — 8-Week Implementation Milestones
Week 1–2

🏗️ Foundation

  • □ FastAPI project setup
  • □ Ingestion pipeline (parse → chunk → embed → store)
  • □ Basic vector search endpoint
  • □ Simple chat completion with retrieved context
  • □ pgvector + Postgres setup
Week 3–4

✨ Quality

  • □ Hybrid search (BM25 + vector)
  • □ Cohere reranker integration
  • □ Conversation history (Redis)
  • □ Streaming responses (SSE)
  • □ Source citations in responses
Week 5–6

🧠 Agentic Upgrade

  • □ Define tool set (search, get_page…)
  • □ Tool-calling loop (LangGraph)
  • □ Query rewriting step
  • □ Smart router (simple vs agentic)
  • □ Langfuse observability
Week 7–8

🚀 Production

  • □ Rate limiting + auth
  • □ Feedback capture (👍👎)
  • □ Content gap detection
  • □ Load testing
  • □ MCP server endpoint
💡 Rule of Thumb
Ship traditional RAG first (Weeks 1–4). It handles 80% of queries well. Add agentic retrieval (Weeks 5–6) when you observe failures on complex, multi-step questions. Agentic RAG earns its 3–10x cost on hard questions — not on FAQs.
